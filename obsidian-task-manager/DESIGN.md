# Obsidian Task Manager 設計書

**作成者:** Manus AI  
**対象:** Obsidianで利用する軽量な個人向けタスク管理環境

## 1. 設計方針

本ツールは、タスクの実体を通常のMarkdownチェックボックスとして保存し、Obsidianの標準機能とTasksコミュニティプラグインだけで運用できる構成とする。独自形式のデータベースを持たないため、タスクは検索、リンク、バックアップ、Git管理の対象として扱える。

TasksプラグインのクエリはVault全体のタスクを一覧化でき、クエリ結果から完了状態を変更できる。標準Templatesプラグインは、定義済みテキストと日付変数をノートへ挿入できる。[1] [2]

## 2. 主要画面

| 画面 | 目的 | 表示内容 |
| --- | --- | --- |
| ホーム | 毎日の起点 | 今日、期限切れ、今週、受信箱へのリンク |
| 受信箱 | 未整理タスクの一時保管 | Inboxノート内の未完了タスク |
| 今日 | 当日の実行判断 | 期限切れ、今日が期限、今日開始のタスク |
| 今週 | 短期計画 | 明日から7日以内に期限が来るタスク |
| プロジェクト | 成果単位の管理 | プロジェクト別タスク、次のアクション、メモ |
| 完了履歴 | 振り返り | 最近完了したタスク |

## 3. データ表現

通常タスクは次の形式で記録する。

```markdown
- [ ] 提案書の初稿を作る 📅 2026-07-17 #task/work ⏫
```

繰り返しタスクは次の形式で記録する。

```markdown
- [ ] 週次レビューを行う 🔁 every Friday 📅 2026-07-17 #task/review
```

| 要素 | 役割 | 例 |
| --- | --- | --- |
| チェックボックス | 状態 | `- [ ]`、`- [x]` |
| 本文 | 次に行う具体的な行動 | `提案書の初稿を作る` |
| 期限 | 完了すべき日 | `📅 2026-07-17` |
| 開始日 | 着手候補日 | `🛫 2026-07-15` |
| 優先度 | 判断の補助 | `⏫`、`🔼`、`🔽` |
| タグ | 分類 | `#task/work` |
| 繰り返し | 再生成条件 | `🔁 every Friday` |

## 4. フォルダ構成

```text
Task Manager/
├── 00 Home.md
├── 01 Inbox/
│   └── Inbox.md
├── 02 Views/
│   ├── Today.md
│   ├── This Week.md
│   └── Completed.md
├── 03 Projects/
│   └── Sample Project.md
├── 90 Archive/
└── 99 Templates/
    ├── Project.md
    ├── Daily Note.md
    └── Task Capture.md
```

Vault設定ファイルは`.obsidian`以下へまとめ、見た目の調整はCSSスニペットとして分離する。導入先に既存設定がある場合、インストーラーは既存ファイルを上書きしない。

## 5. 操作フロー

### 5.1 収集

思いついたタスクを`01 Inbox/Inbox.md`へ追加する。この段階では期限やプロジェクトを必須にしない。

### 5.2 整理

毎日または週次レビューで受信箱を確認し、不要なタスクを削除し、2分以内で終わる内容を完了し、残りには期限、優先度、対象プロジェクトを付ける。

### 5.3 実行

`02 Views/Today.md`を開き、期限切れ、今日が期限、今日開始の順に確認する。クエリ結果のチェックボックスを操作して完了にする。

### 5.4 振り返り

`02 Views/Completed.md`で最近の完了履歴を確認し、未完了の期限切れタスクを再設定する。

## 6. 実装範囲

初期版では、通知やOS常駐処理を実装しない。Obsidianを開いているときに確認するローカルファーストなタスク管理を対象とする。将来、カレンダー連携、通知、専用コマンド、モバイル最適化が必要になった場合は、カスタムプラグイン版へ拡張できる構造とする。
